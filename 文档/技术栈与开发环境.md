当前 Vue 页面显示项目管理和 Agent 对话视图，读取 `/api/health`、项目与环境 API，并提供 Agent 状态/消息入口。M3 对话页面可展示本次模型请求轮次和只读工具调用、结果；会话暂不持久化。首页总览和任务执行界面仍未实现。

M2 的项目识别入口为 `GET /api/v1/projects/{id}/pom-candidates`（仅查找登记目录下最多 4 层、最多 5000 个目录项中的 `pom.xml`，跳过 `.git`、`target`、`node_modules` 等目录）及 `POST /api/v1/projects/{id}/inspect`（提交用户选择的相对路径）。后端限制选中文件必须位于登记目录内且名为 `pom.xml`。环境扫描入口为 `GET /api/v1/environment/snapshot` 和 `POST /api/v1/environment/scan`。这些操作不运行用户项目脚本，不修改项目文件或系统环境。2026-10-16 页面验收确认：JDK 21.0.3、Maven 3.9.4 可用，Git 未发现；`devmate-server\pom.xml` 识别为 Spring Boot · Maven，Java 要求 21。异常/超时行为待验。

M3 Agent 接口包括 `GET /api/v1/agent/status`、`GET/PUT /api/v1/agent/settings`、`POST /api/v1/agent/settings/test` 和 `POST /api/v1/agent/messages`。设置页使用 DeepSeek 官方 OpenAI 兼容接口选择模型、提交 API Key 并发起连接测试。密钥仅暂存在后端进程内存，不回传、不持久化；重启后需重新输入。`application.yml` 将 Spring AI 的聊天、语音、图片、嵌入和审核模型自动配置设为 `none`；Agent 聊天模型由后端在收到设置后动态创建，避免 starter 在启动期因缺少 OpenAI Key 而失败。每次消息按请求构造 Spring AI 工具白名单：始终提供 `scan_environment`，只有用户关联项目并明确选择有效 Maven 配置时才提供 `inspect_project`。显式使用 `internalToolExecutionEnabled=false`，后端每轮查看模型响应后再调用 `ToolCallingManager`；最多执行 3 轮/次请求，并把轮次、工具名、参数及结果返回前端。不持久化对话，不记录模型内部推理。消息和传给模型的事实会发往 DeepSeek；未输入密钥时不会发送。

## 产品运行边界

- V1 用户项目范围：Windows 上常规 Java / Spring Boot + Maven 项目。
- Node.js 用户项目支持放在 V1.1；DevMate 自己的 Vue 前端仍通过 Node.js 构建。
- 后端默认监听 `127.0.0.1:8080`；前端 Vite 开发服务器监听 `127.0.0.1` 并代理 `/api`。
- 项目运行时优先使用进程级 `JAVA_HOME`、`PATH` 和工具版本配置；默认不修改系统全局环境变量。
- 安装工具、运行项目脚本、修改系统环境或受管项目配置前，必须经过针对该操作的明确审批。
- AI 输出不得作为任意 Shell 命令直接执行；所有变更动作须经过程序定义的类型、参数和权限校验。

## 本机环境记录

本机环境会变化，版本信息应标注观察日期并通过版本查询命令重新确认。2026-10-13 实测：终端 `java -version` 为 JDK 11.0.28；Maven 3.9.4 使用 `E:\learn\java\jdk` 下的 JDK 21.0.3；Node.js 24.19.0、npm 11.17.0。Spring Boot 启动日志与 `/api/health` 响应均显示服务 JVM 为 Java 21.0.3。启动 Maven 时使用了临时 settings 与临时本地仓库，没有更改全局 Maven 设置。

本轮 M0 的 HTTP 观察：`http://127.0.0.1:5173/` 返回 200；`http://127.0.0.1:8080/api/health` 直连及经 `http://127.0.0.1:5173/api/health` 的 Vite 代理都返回 `{"status":"UP","application":"devmate","javaVersion":"21.0.3"}`。浏览器 Network 面板仍需学习者亲自观察并解释。
