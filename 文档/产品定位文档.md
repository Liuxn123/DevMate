# DevMate 产品定位文档
**项目名称：** DevMate  
**产品英文定位：** AI-Powered Local Development Agent  
**产品类型：** AI Agent + 本地开发环境管理工具  
**首发平台：** Windows 11  
**文档版本：** V1.0  
**文档日期：** 2026-10-09  
**状态：** 产品方向已确认，V1 功能范围建议稿

---

## 产品概述
DevMate 是一款面向开发者的本地项目启动与开发环境智能管理工具。

产品以 Git 仓库或本地项目为入口，通过 AI Agent 自动识别项目技术栈、分析运行要求、检测本地开发环境、安装缺失工具、管理依赖与配置，并在构建或启动失败时进行智能诊断和辅助修复。

DevMate 采用统一工具仓库与项目级环境配置的管理方式，减少不同项目之间的工具版本冲突，并允许用户自定义工具安装目录、依赖缓存目录和项目存储位置。

**产品愿景：让开发者从获取项目代码到成功运行项目的过程，尽可能自动化、标准化和可视化。**

## 目标用户
核心用户为 Windows 平台上的 Java 后端开发者，尤其是经常需要运行陌生项目、管理多个 JDK 版本或处理复杂开发环境问题的开发者。

初期聚焦个人开发者、学生以及需要频繁切换项目的开发人员。

后续可扩展到 Python、Node.js 和其他开发生态，但不纳入 V1 的完整支持范围。

## 核心价值
**降低项目启动成本**

用户无需逐项研究项目文档并手动安装所有环境依赖，DevMate 能够识别项目需求并提供可执行的安装和配置方案。

**统一开发环境管理**

集中管理 JDK、Maven 等开发工具，允许不同项目绑定不同版本，并统一规划工具目录、依赖缓存和项目配置。

**智能诊断与自动修复**

当环境检测、项目构建或启动失败时，Agent 根据实际错误信息分析原因，生成修复计划，在用户授权后执行修复并重新验证。

**可视化与可追溯**

所有关键操作提供执行进度、实时日志、环境变更记录和结果反馈，避免传统脚本式自动化过程不透明的问题。

## 产品核心场景
用户获取一个新的 Spring Boot 项目，希望将其部署到指定的本地目录并成功运行。

典型操作过程：

+ 用户输入 Git 仓库地址，选择项目目录。
+ DevMate 获取项目并识别技术栈、JDK 版本、Maven 配置及启动要求。
+ 系统检测现有开发工具，优先复用兼容版本。
+ 对缺失或不兼容的工具，生成安装和配置计划。
+ 用户审核安装路径、执行命令和配置修改。
+ DevMate 完成环境准备、依赖下载与项目构建。
+ 启动项目并检查运行状态。
+ 如发生错误，Agent 分析日志、提出修复方案，经确认后执行并再次验证。
+ 最终展示项目状态、访问地址、关联环境和执行记录。

**目标体验：用户明确项目和运行目标，DevMate 负责协助完成中间过程。**

### 项目支持边界
V1 以常规单服务 Spring Boot + Maven 项目为完整支持目标，优先验证不依赖复杂外部基础设施的项目。

多模块 Maven 项目可进行识别和基础分析，但不承诺完整自动部署。

Git 仓库初期支持公开 HTTPS 仓库；私有仓库可以复用本机已有的 Git 凭据，但 V1 不建设独立的凭据管理系统。

### 环境管理边界
DevMate 将工具按版本安装到统一目录，例如：

`D:\DevMate\tools\jdk\17`

`D:\DevMate\tools\maven\3.9`

`D:\DevMate\cache\maven`

每个项目保存自己的环境绑定配置，项目启动时由 DevMate 设置对应进程的环境变量。

默认不修改系统全局 JAVA_HOME 或 PATH，以降低对其他项目的影响。

项目级隔离主要指工具版本、进程环境变量和运行参数隔离，不承诺完整文件系统或操作系统级隔离。

### Agent 权限边界
Agent 可以主动分析本地环境、读取必要配置、检查版本和处理构建日志。

下载工具、执行项目构建脚本、安装依赖、修改配置等操作必须有明确授权。

允许在用户确认后受控修改项目配置文件，例如 `application.yml`、`application.properties`。

对于 `pom.xml` 等影响构建行为的文件，必须展示具体差异并单独确认，不自动进行大规模依赖重写。

默认禁止 Agent 修改 Java 业务源代码、删除无关文件、直接修改 Git 历史或执行未经批准的高风险系统操作。

配置修改前保留备份，记录修改内容，支持在可行范围内恢复原配置。

### 自动修复范围
V1 优先支持以下可识别、可验证的问题：

+ JDK 缺失或版本不兼容。
+ JAVA_HOME、PATH、工具路径配置错误。
+ Maven 不可用、配置错误或部分依赖解析失败。
+ 项目启动端口冲突。
+ 项目配置文件中常见的路径、端口问题。
+ 常见构建与启动异常的日志分析。

MySQL、Redis 等外部服务只进行基础依赖识别、连接检测和问题提示，不负责自动安装部署完整服务。

对于无法确定安全修复方式的问题，DevMate 应终止自动修复并向用户说明原因，而不是反复执行未经验证的命令。

## V1 不包含的功能
+ Linux、macOS 平台完整支持。
+ Docker、Kubernetes、云端部署及服务器运维。
+ 多 Agent 协作及复杂工作流平台。
+ Python、Node.js 等其他语言的完整项目启动能力。
+ 任意第三方软件的通用安装管理。
+ MySQL、Redis 等中间件的自动化全生命周期管理。
+ 自动修改业务逻辑及通用代码修复。
+ 多设备同步、团队协作和云端账户系统。
+ 无边界的系统命令自主执行。

上述功能不代表永久排除，而是不作为 V1 交付条件。

## 产品交互原则
**目标驱动：** 用户告诉 DevMate 希望运行什么项目，而非逐条指定技术操作。

**计划先行：** 对实际环境变更提供执行计划、安装位置、操作内容和风险提示。

**安全可控：** 敏感操作必须授权，尽量避免全局环境污染。

**过程透明：** 每项操作都有可观察状态和执行记录。

**结果验证：** 以构建结果、进程状态和实际服务可用性作为运行成功的证据，不依赖 AI 主观判断。

**失败可解释：** 对无法自动处理的问题输出明确的阻塞原因和后续建议。

## V1 界面范围
**项目工作台**

用于导入项目、查看项目列表、管理项目环境配置、启动和停止项目。

**环境管理中心**

查看已安装工具、工具版本、安装位置、缓存位置，以及项目和工具之间的绑定关系。

**任务执行与诊断中心**

查看任务计划、操作审批、执行进度、实时日志、Agent 故障分析、修复操作和验证结果。

第一版以功能清晰、操作直观为优先，不开发复杂的可视化工作流编辑器。

## V1 验收标准
V1 至少应通过以下真实场景的完整验证：

**新项目启动**

对一个符合支持范围、环境条件完整的 Spring Boot 项目，能够从 Git 导入并完成构建、启动和运行验证。

**缺失环境安装**

当所需 JDK 不存在时，能够识别缺失版本，按用户指定路径安装，并完成项目环境绑定。

**多项目版本共存**

两个需要不同 JDK 版本的项目可以分别使用自己的配置运行，无需反复修改系统全局 JAVA_HOME。

**智能故障修复**

对于预先设计的典型环境故障，Agent 能够解释原因、生成计划、经授权修复，并以重新执行的结果证明问题是否解决。

**配置修改安全性**

涉及项目配置变更时，能够展示差异、获得确认、保留备份并记录操作结果。

**运行状态可观察**

用户能够查看当前项目状态、任务步骤、执行日志、失败原因和成功验证依据。

## 产品演进方向
**V1 — Java 项目智能启动**

完成项目导入、环境检测、工具安装、项目启动、智能诊断和受控修复的核心闭环。

**V2 — 多技术栈开发环境管理**

扩展 Node.js、Python 等生态，完善环境管理中心、工具版本管理和缓存管理能力。

**V3 — 智能开发工作台**

逐步增加项目环境模板、环境迁移、更多开发服务集成及高级自动化能力。

未来版本的功能应根据真实使用反馈确定，不提前将其纳入 V1 的实现负担。

---

## 产品定位总结
**DevMate 是一个以项目成功运行为目标、以统一环境管理为基础、以 Agent 智能诊断与受控修复为差异化能力的 Windows 本地开发助手。**

V1 聚焦 Java Spring Boot + Maven 场景，优先完成从仓库导入到本地运行的完整闭环，在保证安全可控的前提下逐步提升自动化程度。
