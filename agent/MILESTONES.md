# DevMate 学习与开发里程碑

## 规划原则

- 以 `文档/` 中的产品、需求与架构资料为目标规格，按小型纵向切片学习和实现。
- 每个里程碑都要先提出预测，运行后记录证据，再解释程序、模型和工具分别做了什么。
- 先把确定性识别、审批、执行和验证做好，再接入 Spring AI；任何模型输出都不能直接作为命令执行。
- 不设置日历死线；按验收证据推进，完成一个里程碑后再拆下一阶段的具体任务。
- 安装工具、运行项目脚本、变更系统环境或修改被管理项目配置前，先取得针对该操作的明确审批。

## AI / Agent 学习与接入路线

Agent 是本项目的核心学习目标，按“先观察工具事实，再让模型选择工具，最后让模型提案并经审批执行”逐步增加能力。每一阶段都保留模型决策、程序校验和工具结果的可观察记录。

| 阶段 | 里程碑 | 学习与实现内容 | 安全边界/验收重点 |
|---|---|---|---|
| 1. 让 Agent 看见事实 | M2 → M3 | 先理解确定性项目识别与环境扫描；再学习 Spring AI 的模型适配、提示词和 Tool Calling，让模型根据用户问题选择只读工具。 | 工具由后端白名单注册；参数由程序校验；限制调用轮数；能追踪模型请求、工具参数、工具结果和最终答复；不写文件、不运行命令。 |
| 2. 让 Agent 规划 | M5 | 学习把自然语言目标转换成固定 Schema 的 `PlanProposal`，包含动作、参数、风险、前置条件和验证方式。 | 后端验证结构、路径和权限；模型只提出方案，不能自行扩大权限或执行。 |
| 3. 让用户批准计划 | M6 | 学习计划版本、内容哈希、状态机和审批记录；审批明确绑定到用户看到的计划版本。 | 计划有变化必须重新审批；拒绝、撤回和过期状态可追溯。 |
| 4. 让程序受控执行 | M7 → M9 | 学习动作模板、参数数组、进程生命周期、日志流、取消与健康验证；Agent 根据结果解释下一步。 | 只执行后端定义的动作；高风险操作先审批；模型生成的命令文本永不直接交给 Shell。 |
| 5. 让 Agent 诊断并提议修复 | M10 → M11 | 学习如何为模型提供经过筛选的项目事实/日志、区分观察与推断，并生成可验证的修复提案。 | 配置写入先备份且用户审批；重跑验证；保存修改差异、执行结果和失败回滚信息。 |

具体 AI 待办见 [TASKS-AI.md](TASKS-AI.md)。M3 使用 Spring AI 1.1.8 的 OpenAI 兼容适配器连接 DeepSeek；用户通过偏好设置选择 DeepSeek 模型并输入 API Key，密钥只保存在后端进程内存，重启后需重新输入。页面提供连接测试。M2 主流程已通过页面验收；M3 仍待构建、配置模型及运行验收。

## 本轮不纳入 V1

Node.js 用户项目支持留到 V1.1；DevMate 自身 Vue 前端仍使用 Node.js 构建。多 Agent、任意 Shell 执行、Docker 全生命周期和自动修改业务源代码不属于本里程碑计划。
