# DevMate 学习与开发里程碑

## 规划原则

- 以 `文档/` 中的产品、需求与架构资料为目标规格，按小型纵向切片学习和实现。
- 每个里程碑都要先提出预测，运行后记录证据，再解释程序、模型和工具分别做了什么。
- 先把确定性识别、审批、执行和验证做好，再接入 Spring AI；任何模型输出都不能直接作为命令执行。
- 不设置日历死线；按验收证据推进，完成一个里程碑后再拆下一阶段的具体任务。
- 安装工具、运行项目脚本、变更系统环境或修改被管理项目配置前，先取得针对该操作的明确审批。

| M8 | 未开始 | 项目环境配置、工具管理与偏好设置 | 项目可绑定兼容的 JDK/Maven；管理工具路径、版本、缓存和全局默认设置；只修改受管子进程环境，不写全局 PATH/JAVA_HOME；工具下载/安装有审批、校验和可追踪记录。 |
| M9 | 未开始 | Spring Boot 项目构建、启动与验证 | 对支持范围内的单体 Spring Boot + Maven 项目，完成导入/识别、环境匹配、构建、启动和健康验证；过程与结果可追溯。 |
| M10 | 未开始 | Agent 诊断与受控修复 | Agent 根据受限上下文和真实日志解释失败、提出结构化修复计划；后端校验且用户审批后才执行；配置改动先备份，修复后重新验证并保存证据。 |
| M11 | 未开始 | V1 集成验收与学习复盘 | 用真实支持范围内项目完成核心闭环，覆盖成功、缺环境、构建失败、审批拒绝和可恢复配置修改；记录 Agent 决策证据、安全边界、已知限制和下一版本范围。 |

## 原型模块与里程碑映射

| 原型模块 | 对应里程碑 | 覆盖内容 |
|---|---|---|
| 首页总览 | M4、M9、M11 | 本机环境摘要、项目和任务状态、最近活动；数据来自真实扫描和任务，不使用原型图中的演示数字。 |
| 环境管理 | M2、M4、M8 | 先展示只读发现结果，再加入版本绑定、工具仓库/缓存配置和经审批的安装。 |
| 项目管理 | M1、M2、M4、M9 | 项目登记、结构识别、环境匹配、部署进展和运行验证。 |
| Agent 对话 | M3、M4、M5、M10 | 只读工具循环、上下文/会话可观察、结构化计划、故障诊断与受控修复。 |
| 任务执行 | M6、M7、M9 | 计划审批、步骤状态、日志、取消/失败处理和最终验证。 |
| 偏好设置 | M8 | 全局路径、模型配置、安全策略等设置；敏感凭据不写入数据库或仓库。 |

原型图用于表达页面结构和目标体验。图中出现的 Node.js/Python 用户项目和示例项目数据不自动扩大 V1 范围：V1 用户项目仍以 Java/Spring Boot + Maven 为准；Node.js 用户项目放到 V1.1。

## 当前推进

M1 的实现和运行验收已通过，学习复盘待补。当前提前推进 M4 的项目管理页面切片，把 SQLite 登记能力接到真实界面；随后继续 M2 只读项目识别和环境扫描，再按计划实现 M3 Agent 循环。M0 的 Network 面板观察作为待补学习项保留。任何安装、写文件、构建或启动动作仍须走后续审批与受控执行里程碑。运行 Maven、安装 npm 依赖或启动开发服务器前，需先确认具体命令与当前环境影响。

## 本轮不纳入 V1

Node.js 用户项目支持留到 V1.1；DevMate 自身 Vue 前端仍使用 Node.js 构建。多 Agent、任意 Shell 执行、Docker 全生命周期和自动修改业务源代码不属于本里程碑计划。
